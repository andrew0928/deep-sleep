# 決策紀錄維護規則

本目錄保存使用者對 deep-sleep 本身的關鍵設計決策，聚焦 CLI 結構、架構、設定方式等影響專案方向的選擇。新增或維護紀錄時遵循以下規則：

1. 使用者明確做出專案設計選擇或批准設計方案時，建立一筆紀錄。原始需求放在 `docs/`；開始實作、Git 初始化／push、認證、指定測試標的及整理文件等操作要求不建立決策紀錄。不要將 agent 的建議、低層實作細節、問題回報或一般詢問當成已批准的決策。
2. 先讀取 `index.md`，以 Asia/Taipei 日期建立 `YYYY-MMDD-NNN/decision.md`。同一天使用下一個三位流水號，一個決策一個目錄，不覆寫既有紀錄。
3. 以繁體中文記錄日期、決策內容、對話依據及背景或影響。引用使用者原文時保持原意；不捏造理由、時間或完成狀態。
4. 新增紀錄後立即更新 `index.md`，依發生順序排列，連結到對應 `decision.md`。
5. 改變先前決策時新增一筆，雙向連結相關紀錄。原始決策保留；可加註被新決策取代，不直接改寫成新結論。
6. 決策與實作／驗收狀態分開；測試與交付狀態維護於需求文件，不另外建立操作紀錄。
7. 更新相關需求文件時保持與決策一致；檢查本地 Markdown 索引連結是否有效。文件修改不需執行磁碟操作或睡眠測試。
