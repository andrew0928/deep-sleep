# 專案決策流水帳

依發生順序記錄使用者對 deep-sleep 本身的關鍵設計選擇，例如 CLI 結構、架構與設定方式。每個決策有獨立目錄及 `decision.md`；產品需求與驗收另見 [需求紀錄](../docs/requirements.md)。

## 記錄方式

- 目錄格式為 `YYYY-MMDD-NNN`，例如 `2026-1010-001`。日期使用 Asia/Taipei；同一天的三位流水號依決策順序遞增，確保一個決策一個目錄。
- 只記錄使用者明確決定或同意的專案設計方案。原始需求放在 `docs/`；開始實作、Git 初始化／push、認證、測試標的指定與文件整理等操作要求不列為專案決策。
- 提問、尚未同意的建議、一般 bug 修正及低層實作細節不自動建立紀錄。
- 說明包含決策內容、對話依據、背景或影響。原文引用與整理出的解讀應清楚區分，不補寫使用者未說過的理由。
- 決策紀錄不代表實作或交付已完成；需要時另註執行狀態。
- 後續更改決策時新增紀錄，連結被取代的紀錄，保留原文與歷史。
- 本批為回填紀錄，依本次對話的先後順序排列；使用本次工作日期 2026-10-11，不推測個別訊息的精確時間。
